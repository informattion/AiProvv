Начало работы

ProvvAI предоставляет HTTP endpoint для отправки сообщений выбранной модели и получения ответа в формате, совместимом со структурой Chat Completions.

Base URL
https://winter-sun-c0a4.agonekg.workers.dev

Основной запрос отправляется методом POST на базовый URL. Тело запроса передаётся в формате JSON.

Авторизация

В примере публичного API используется заголовок Bearer. Подставьте собственный ключ вместо заполнителя.

HTTP headers
Content-Type: application/json
Authorization: Bearer YOUR_PROVV_API_KEY
Не размещайте секретный API-ключ в открытом HTML или JavaScript, который отправляется браузеру. Для клиентских приложений используйте собственный сервер-посредник.

Формат запроса

Минимальный пример содержит модель и массив сообщений. В коде самого приложения также используются поля provider и max_tokens; доступность дополнительных параметров зависит от реализации сервера.

JSON body
{
  "model": "Prov-claude-fable-5",
  "messages": [
    { "role": "user", "content": "Привет!" }
  ]
}
  • model — идентификатор модели. В примере внешнего API используется префикс Prov-.
  • messages — массив сообщений с полями role и content.
  • provider — используется внутренним клиентом ProvvAI для выбора провайдера.
  • max_tokens — лимит ответа, передаваемый внутренним клиентом.

Ответ сервера

Внешний пример ожидает текст ответа в choices[0].message.content. Клиент ProvvAI дополнительно умеет читать варианты result и message.content.

Response example
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "Привет! Чем могу помочь?"
      }
    }
  ]
}

Модели

В исходном интерфейсе перечислены следующие идентификаторы. Для внешнего API используйте формат имени, указанный в его примере, и проверьте актуальность доступности модели в своём аккаунте.

  • Anthropic: claude-fable-5, claude-opus-5, claude-sonnet-5
  • OpenAI: gpt-6-astra, gpt-6-luna, gpt-5.5
  • Google: gemini-3.1-pro
  • DeepSeek: deepseek-v4.1-flash
  • Cloudflare: @cf/meta/llama-3.3-70b-instruct-fp8-fast, @cf/meta/llama-3.1-8b-instruct

Обработка ошибок

Проверяйте HTTP-статус ответа до чтения полей результата. В текущем клиенте отдельно обрабатывается статус 401; для остальных ошибок отображается поле error, если оно присутствует.

JavaScript error handling
const response = await fetch(API_URL, options);
const data = await response.json().catch(() => ({}));

if (!response.ok || data.success === false) {
  const message = data.error?.message || data.error || `HTTP ${response.status}`;
  throw new Error(message);
}

Полный перечень кодов ошибок и их схемы в исходном проекте не описаны. Не предполагайте наличие специальных кодов, пока они не подтверждены серверной реализацией.

Что подтверждено текущей реализацией

В предоставленном HTML присутствует один POST endpoint, JSON-тело с моделью и сообщениями, cookie-сессия для встроенного чата и пример Bearer-заголовка для внешнего вызова. В проекте не обнаружена спецификация или реализация отдельных маршрутов для embeddings, изображений, аудио, файлов, tools/function calling или streaming.

Примеры на разных языках — это клиенты одного HTTP endpoint, а не отдельные SDK. Для точного описания всех функций API понадобится серверный Worker или OpenAPI-схема.
